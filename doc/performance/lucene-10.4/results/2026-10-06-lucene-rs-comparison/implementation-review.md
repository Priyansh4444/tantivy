# Implementation review

Read the complete shared library, both workers, port prepare, controller, stage runner and synthesis. Read the Cargo manifest, final build receipt/source heads and retained frozen ruler for supporting evidence. No tests, heavy jobs or source changes were performed. Findings below are the concrete blockers before claiming a fully gated, bounded timing run.

throughput checkpoint: n/a, read-only investigation

1. **The reused Tantivy index is not bound to its retained complete payload proof.** `balanced.py:84–89` checks the current port file map against its fresh full audit, but performs no corresponding comparison of `TINDEX` with the retained `native-profile-aligned-oct05/frozen-ruler.json` artifact hashes. `identity()` merely captures the current index and checks that it remains unchanged later. READY statistics and the finite query suite cannot establish complete postings/positions identity for an index that changed before verification. Minimal fix: before opening workers, extract the Tantivy index's complete non-lock filename/hash map from the frozen ruler and require exact equality with `index_files(TINDEX)`, including missing/extra files. Retain that ruler identity in the run provenance. This reuses the existing hash pass and avoids another full Tantivy decoder audit.

2. **The declared total timing deadline does not bound startup and warmup.** `balanced.py:132` starts the 2700-second clock, but its only deadline check is at line 155 after a measured cell. Both worker startups and every warmup request at lines 136–143 can run past the entire budget before that check executes. Minimal fix: establish one absolute monotonic deadline, check it before each startup and every warmup/measured request, and cap each read/request timeout by the remaining total budget. Retain the incomplete/error receipt on exhaustion. The same admission path should apply any explicit overall verification bound; the current verification loop only has per-request limits.

3. **Timing admission lacks the required own-job-idle check.** `measure()` accepts a correctness receipt and artifact hashes, then begins warmup; `telemetry()` logs only the top process snapshot and never rejects or waits for own compilation/index/audit/test/hash jobs. Such jobs can leave sources and indices unchanged and still pass the final receipt while contaminating all samples. Minimal fix: before invoking measurement, explicitly wait for the known preparation/test/audit processes to finish and retain an own-job-idle receipt identifying the checked jobs. A controller admission check or a root-owned external check is sufficient; leave user processes untouched. Root has preparation/fixtures running during this review, so this is a timing-admission requirement, not a claim that timing has already overlapped them.
